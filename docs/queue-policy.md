# 대기열 안전 정책 · 앱 0.3.0

사용자가 승인한 원칙은 규칙을 끄면 해당 미전송 항목도 멈추고, 계정 변경·연결 해제 시 이전 항목을 새 계정으로 보내지 않는 것이다. 삭제는 영향받는 항목 수를 보여주고 별도 확인한다.

| 사용자 행동 | 이후 수집 | 이전 미전송 항목 |
| --- | --- | --- |
| 규칙 끄기 | 해당 규칙 적용 중지 | 그 규칙과 연결된 항목 보류. 여러 규칙에 맞았어도 하나를 끄면 보수적으로 보류 |
| 규칙 다시 켜기 | 이후 수집 항목에만 적용 | 자동 재개 없음 |
| 계정 다시 연결 | Google 동의 후 연결 확인. 전송은 OFF | 모든 미전송 항목 보류. 자동 재개 없음 |
| 계정 변경 / 연결 해제 | 기존 로컬 연결과 메모리 토큰 제거, 전송 OFF. 변경이면 새 연결을 직접 시작 | 원문은 유지하며 보류. 새 계정으로 이전 항목을 전송하지 않음 |
| Gmail 전송 켜기 | 수신자·원문 전송을 확인한 시점 이후 수집 항목만 전송 가능 | 이전 PENDING/RETRYABLE도 보류. 기존 보류 항목은 유지 |
| 수집 일시정지 | 수집과 전송 모두 중지 | 원문 유지·보류. 수집 재개만으로 전송을 켜지 않음 |
| 미전송 항목 삭제 | 규칙·계정 연결·Gmail 접수 기록은 유지 | 확인한 대상과 원문을 로컬에서 삭제 |

계정 연결 해제는 Google 계정 삭제나 원격 grant 취소가 아니다. 앱에 저장한 연결 정보만 제거한다. 메모리 토큰을 제거하고 계정 epoch를 증가시켜 오래된 승인·토큰 새로고침 콜백이 연결을 복원하지 못하게 한다.

삭제 확인은 단순 개수가 아닌 **정확한 항목 ID 집합**을 다시 검사한다. 대상이 바뀌면 삭제하지 않고 최신 수를 보여주며 다시 확인한다. 확인과 변경은 Room transaction 및 전송 판단과 공유하는 정책 gate 안에서 처리한다. 규칙·계정 변경 확인도 대상 집합을 다시 확인한다.

각 신규 항목은 일치한 규칙 ID와 수집 당시 계정 epoch·수신자에 바인딩한다. worker는 현재 규칙, 활성 시점, 수신자, epoch, 전송 허용 시점과 현재 SENDING 상태를 확인한다. 메일 투영이 준비된 후 실제 transport 직전에도 다시 확인한다. 정책으로 보류된 항목은 늦은 retry 결과로 RETRYABLE 상태가 되지 않는다.

이미 제출하기 시작한 요청은 되돌릴 수 없으며 UI가 이를 설명한다. 승인된 요청이 실제로 Gmail에 접수되면 그 사실을 기록한다. 결과 미확인 항목은 자동 재전송하지 않는다. 사용자 확인 없이 보류 큐를 재개하는 경로는 제공하지 않는다.

Room v1→v2 migration은 원문과 완료/미확인 결과를 보존한다. 과거 PENDING/RETRYABLE/SENDING은 안전 보류한다. 규칙 출처가 없는 과거 항목은 같은 채널·소스의 규칙을 끌 때 보수적으로 보류하며, 제출 시 출처가 없으면 전송하지 않는다. 앱의 정책 버전 최초 준비 시 Gmail 전송을 OFF로 둔다. destructive migration과 사용자 DB 초기화는 사용하지 않는다.

앱 선택은 MAIN/LAUNCHER intent를 queries로 선언한다. 홈 화면에서 실행할 수 있는 앱만 조회하며 EventRelay와 Gmail은 제외한다. QUERY_ALL_PACKAGES나 Gmail 추가 scope는 없다. 백그라운드 전용 앱은 이 목록에 표시되지 않을 수 있다.

원문 화면은 FLAG_SECURE를 유지한다. 진단 복사는 버전·Android API·권한/연결/수집/전송 여부·항목 수·오류 발생 여부만 허용한다. 본문, 발신자, 앱 목록, 이메일, 토큰과 원래 예외·오류 문자열은 복사하지 않는다.
